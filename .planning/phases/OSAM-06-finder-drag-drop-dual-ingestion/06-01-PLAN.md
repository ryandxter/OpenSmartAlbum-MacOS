## Context & Strategy

In OpenSmartAlbum v1.0.77, dragging image files or folders from macOS Finder into the application fails completely because native window drag-drop is disabled in `tauri.conf.json` (`"dragDropEnabled": false`), rejecting all OS-level file drops at the `WKWebView` layer. Furthermore, neither `WorkspaceLayout.tsx` nor the canvas components register Tauri 2 window drag-drop event listeners.

Phase 06 addresses this by:
1. **Enabling Native OS Window Drag-Drop:** Toggling `"dragDropEnabled": true` in `src-tauri/tauri.conf.json`.
2. **Contextual Drop Target Hit-Testing:** Listening to Tauri 2 `getCurrentWebview().onDragDropEvent` in `WorkspaceLayout.tsx`. Converting physical cursor coordinates (`PhysicalPosition`) into logical CSS client coordinates via `window.devicePixelRatio`, distinguishing whether the user is dropping onto the **Filmstrip Tray** or the **Canvas Area**.
3. **Dual Ingestion Routing:**
   - **Filmstrip Tray Drop (D-01):** Ingests photos/folders into the project library via `usePhotoStore.getState().importPaths()`, background thumbnail extraction, marked unused.
   - **Canvas Drop (D-02):** Ingests files into the library in the background, then immediately places them on the targeted spread (Album Mode) or slide (Carousel Mode).
     - If dropped over an existing frame: replaces frame image asset.
     - If dropped on an empty spread/slide with multiple photos: executes SmartAlbums-standard **Smart Auto-Partitioning** (D-03) using `generateAdaptiveLayoutVariations` or box partitioning.
     - If dropped on a spread/slide with existing elements: appends photos using non-overlapping batch placement (`calculatePhotoBatchPlacement`).
4. **Frosted Glass Drop Zone HUD (D-05):** Displaying a full-window semi-transparent backdrop with high-contrast dashed blue borders (`#3b82f6`) and contextual labels indicating the active drop action.

**Target Files:**

**Decisions Addressed:** [D-01](file:///.planning/phases/OSAM-06-finder-drag-drop-dual-ingestion/06-CONTEXT.md#L17-L20), [D-02](file:///.planning/phases/OSAM-06-finder-drag-drop-dual-ingestion/06-CONTEXT.md#L21-L27)

**Implementation Details:**
1. In `src/stores/photoStore.ts`:
   - Export an ingestion helper or add store method `importPathsAndGetPhotos: (projectId: string, paths: string[], folderId?: string | null) => Promise<Photo[]>`:
     - Directly calls `invoke<Photo[]>('import_file_paths', { projectId, paths, folderId })`.
     - Updates `photoStore` state (`photos`, triggers `syncAlbumFramePhotoAssets`, `markLibraryChanged`).
     - Returns the array of new `Photo` objects matching the ingested paths so canvas placement can immediately resolve their IDs, dimensions, and aspect ratios.
2. In `src/features/workspace/WorkspaceLayout.tsx`:
   - Import `getCurrentWebview` from `@tauri-apps/api/webview`.
   - Setup state:
     ```ts
     const [isFinderDragging, setIsFinderDragging] = useState(false);
     const [finderDropZone, setFinderDropZone] = useState<'canvas' | 'filmstrip' | 'none'>('none');
     const [draggedFileCount, setDraggedFileCount] = useState(0);
     ```
   - Attach a `useEffect` hook listening to `getCurrentWebview().onDragDropEvent`:
     ```ts
     useEffect(() => {
       let unlisten: (() => void) | undefined;
       getCurrentWebview().onDragDropEvent((event) => {
         const payload = event.payload;
         if (payload.type === 'enter') {
           setIsFinderDragging(true);
           setDraggedFileCount(payload.paths?.length || 0);
         } else if (payload.type === 'over') {
           // Physical position to logical client position
           const clientX = payload.position.x / window.devicePixelRatio;
           const clientY = payload.position.y / window.devicePixelRatio;
           // Determine whether point is inside Filmstrip Tray or Canvas
           const zone = resolveDropTargetZone(clientX, clientY);
           setFinderDropZone(zone);
         } else if (payload.type === 'leave') {
           setIsFinderDragging(false);
           setFinderDropZone('none');
           setDraggedFileCount(0);
         } else if (payload.type === 'drop') {
           setIsFinderDragging(false);
           setFinderDropZone('none');
           setDraggedFileCount(0);
           handleFinderDrop(payload.paths, payload.position);
         }
       }).then((fn) => { unlisten = fn; });
       return () => { if (unlisten) unlisten(); };
     }, [currentProject, activeMode]);
     ```
   - Implement `resolveDropTargetZone(clientX: number, clientY: number)`:
     - Check if `clientY` is within the bottom filmstrip container bounds (if filmstrip is visible/open), otherwise inside center canvas area.
   - Implement `handleFinderDrop(paths: string[], physicalPos: { x: number; y: number })`:
     - Filter supported image extensions (`jpg, jpeg, png, tiff, tif, webp, heic, heif, raw, cr2, nef, arw, dng`) or directories.
     - If dropped on **Filmstrip Tray** (`finderDropZone === 'filmstrip'`):
       - Execute D-01: call `usePhotoStore.getState().importPaths(currentProject.id, validPaths)`.
       - Show notification toast: `Importing X photo(s) from Finder into library...`.
     - If dropped on **Canvas** (`finderDropZone === 'canvas'`):
       - Execute D-02 / D-03: delegate to Canvas drop placement handler (Task 4).
