# Plan 01-01: Tauri 2 macOS Configuration & Win32 FFI Elimination

## Metadata
- **Phase:** 01 — macOS Foundation & Pure Rust Pipeline
- **Plan ID:** 01-01
- **Requirements:** PLAT-01, PLAT-03
- **Goal:** Configure Tauri 2 for Universal macOS bundle distribution (`.app` and `.dmg`), generate hardened runtime entitlements, eliminate Win32-specific FFI bindings (`EmptyWorkingSet`, GDI color sampling), and enable APFS/HFS+ case-insensitive path normalization.
- **Dependencies:** None (first plan of Phase 1)

---

## Context & Strategy

The codebase was originally developed targeting Windows, containing Win32 FFI declarations in memory management (`EmptyWorkingSet`), color screen sampling (`gdi32`/`user32`), and Windows Registry font enumeration. Additionally, file path comparisons and identity hashes assume case-sensitive comparisons on non-Windows platforms, which causes duplicate photo imports and link breakage on case-insensitive APFS/HFS+ filesystems on macOS.

This plan removes these Windows-only assumptions and configures the native macOS runtime:
1. Rebrand bundle configuration in `tauri.conf.json` to `com.opensmartalbum.app` / `OpenSmartAlbum`, target macOS 13.0 (Ventura) minimum system version, configure DMG window and icon coordinates, and create `Entitlements.plist`.
2. Decouple Win32 FFI:
   - Make `trim_process_memory()` a clean cross-platform no-op on Darwin/Linux while preserving the public API for existing callers (`photo_commands.rs`).
   - Remove Win32 GDI color picking FFI from `sample_screen_color`, returning an explicit error code (`NATIVE_SAMPLING_UNAVAILABLE`) so the webview frontend (`ColorPicker.tsx`) immediately and smoothly uses its DOM/Canvas color sampler.
3. Fix APFS case-preserving normalization in `photo_commands.rs:path_identity` and `db/package_io.rs:same_path`.

### Task 2: Win32 FFI Decoupling (Memory Trimming & Color Sampling)

- **Files:**
  - `src-tauri/src/photo_engine/mod.rs`
  - `src-tauri/src/commands/app_commands.rs`

- **Action:**
  1. In `src-tauri/src/photo_engine/mod.rs`:
     - Update `trim_process_memory()`:
       - Retain the public function signature `pub fn trim_process_memory()`.
       - Document that Darwin and Linux utilize automatic OS virtual memory compaction and page reclamation via `libsystem_malloc` / kernel VM, where user-space working set eviction is unnecessary.
       - Ensure non-Windows targets compile as a clean zero-cost no-op without any unused symbol warnings or Win32 imports.
  2. In `src-tauri/src/commands/app_commands.rs`:
     - Inspect `mod win32_color` (lines 95–114) and `sample_screen_color` (lines 116–156).
     - Keep `win32_color` strictly guarded under `#[cfg(target_os = "windows")]`.
     - In `sample_screen_color`:
       - On non-Windows (`#[cfg(not(target_os = "windows"))]`), replace the current hardcoded `#FFFFFF` return value with an explicit error: `Err("NATIVE_SAMPLING_UNAVAILABLE".to_string())`.
       - This signals the frontend (`src/components/ui/ColorPicker.tsx:handleEyeDropper`) to immediately fall back to its native Web/DOM canvas sampling without delay or returning inaccurate white pixels.

- **Verification:**
  - `cargo check --manifest-path src-tauri/Cargo.toml` compiles cleanly with zero warnings or errors.

- **Acceptance Criteria:**
  - No Win32 FFI functions are invoked on macOS Darwin targets.
  - `sample_screen_color` returns an explicit error on non-Windows targets rather than returning a deceptive `#FFFFFF`.
</task>

<task id="01-01-T3">
### Task 3: APFS/HFS+ Case-Preserving Path Normalization

- **Files:**
  - `src-tauri/src/commands/photo_commands.rs`
  - `src-tauri/src/db/package_io.rs`

- **Action:**
  1. In `src-tauri/src/commands/photo_commands.rs`:
     - In `path_identity` (lines 204–211):
       - Change the conditional compilation directive from `#[cfg(windows)]` to `#[cfg(any(windows, target_os = "macos"))]`.
       - On macOS, APFS and HFS+ are case-insensitive by default. Normalizing the path string with `.trim_start_matches("//?/").to_lowercase()` ensures files imported with different casing variants are identified as identical, preventing duplicate imports and link breaks.
       - Non-Windows, non-macOS targets (e.g. Linux ext4) remain case-sensitive (`#[cfg(not(any(windows, target_os = "macos")))]`).
  2. In `src-tauri/src/db/package_io.rs`:
     - In `same_path` (lines 61–76):
       - Update line 73 from `if cfg!(windows)` to `if cfg!(any(windows, target_os = "macos"))`.
       - Use `a.to_string_lossy().eq_ignore_ascii_case(&b.to_string_lossy())` on macOS to ensure project file save-as and identity preservation work correctly on APFS volumes.

- **Verification:**
  - Run `cargo test --manifest-path src-tauri/Cargo.toml db::package_io::`
  - Ensure all `package_io` unit tests pass without failure.

- **Acceptance Criteria:**
  - `path_identity` applies lowercase normalization on macOS Darwin.
  - `same_path` performs case-insensitive ASCII comparison on macOS Darwin.
  - Existing `package_io` tests pass cleanly.
</task>
