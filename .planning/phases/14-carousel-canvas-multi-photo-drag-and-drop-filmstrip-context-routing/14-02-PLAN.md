- **Plan:** 14-02

- **Requirements Covered:** `CAR-03`, `CAR-04`
- **Status:** Pending Execution

## Context & Strategy
Currently, dropping $N$ photos onto a carousel slide loops over `addPhotoFrame`, pushing $N$ separate undo entries to the history stack and placing photos into a crude 2-column grid. Furthermore, right-clicking photos in the Filmstrip Tray or double-clicking cards in Social Carousel mode silently mutates the background Print Album spread (`useAlbumStore`), failing to update the visible carousel slide and misleading users.

This plan resolves these architectural defects by:
- Implementing `addPhotoFrames(slideIndex, photos, options)` in `carouselStore.ts` that commits a single `pushHistory()` entry, combines existing frames with new photos into an adaptive set, invokes the R-BSP layout generator (`generateDynamicVariations`), and preserves custom borders, corner radii, and shape masks.
- Updating `CarouselCanvas.tsx` to invoke `addPhotoFrames` on multi-drop and single-drop events.
- Threading `activeMode: 'print' | 'carousel'` into `PhotoContextMenu.tsx` with dynamic microcopy (`"Place on Active Slide"` / `"Place X Photos on Slide"` vs `"Place on Spread Canvas"`) and routing photo placement to `useCarouselStore.getState().addPhotoFrames`.
- Updating `FilmstripTray.tsx` double-click handling to detect selected frames on the active carousel slide for in-place replacement or dynamic appending.
- Creating an automated test suite in `tests/carousel-drag-context.test.ts` verifying atomic batch history, R-BSP reflow, style preservation, and context routing.

## Tasks

<task id="14-02-01">
### Task 1: Implement `addPhotoFrames` in `src/stores/carouselStore.ts` and Wire in `CarouselCanvas.tsx`
**Target Files:**
- `src/stores/carouselStore.ts`
- `src/features/carousel/CarouselCanvas.tsx`

1. **Add `addPhotoFrames` to `CarouselState`:**
   ```typescript
   addPhotoFrames: (
     slideIndex: number,
     photos: Photo[],
     options?: { targetFrameId?: string; isReplace?: boolean }
   ) => string[];
   ```
2. **Implement Atomic Layout Reflow with Style Preservation:**
   - Call `pushHistory()` exactly **once** at the start of the method.
   - Separate `existingPhotoFrames` from `nonPhotoElements` on the targeted slide.
   - **Case A (Single-Photo Frame Replacement):**
     If `photos.length === 1 && (options?.isReplace || options?.targetFrameId)`:
     - Locate the target frame by `options.targetFrameId`.
     - Update `photoId`, `filePath`, `fileName`, `previewPath`, `thumbnailPath`, and recalculate `photoAspect`.
     - Reset crop (`cropX: 0, cropY: 0, cropScale: 1.0`).
     - Preserve existing frame geometry (`x, y, width, height`), borders, corner radii, and shape masks.
     - Commit via single `set()`.
   - **Case B (Fresh Batch Drop or Smart Reflow):**
     - Map existing photo frames into `AdaptivePhoto` objects, caching styling metadata (`borderEnabled`, `borderWidth`, `borderColor`, `borderStyle`, `cornerRadius`, `cornerRadiusTl`, `cornerRadiusTr`, `cornerRadiusBr`, `cornerRadiusBl`, `shapeType`, `customSvgPath`, `shadowEnabled`, `shadowColor`, etc.).
     - Map incoming `Photo[]` objects into `AdaptivePhoto` objects.
     - Invoke `generateDynamicVariations({ containerWidth: slideWidthPx, containerHeight: slideHeightPx, spacing: 16, isSpread: false }, combinedPhotos)`.
     - Take `variations[0]` and project rects into continuous slide coordinates: `x: slideStartX + rect.x`, `y: rect.y`.
     - Re-apply cached styling metadata to the corresponding existing frames (fixing WARN-03).
     - Commit `slides: updatedSlides`, `selectedFrameIds: newFrameIds`, `selectedFrameId: newFrameIds[0] || null`, `slideLayoutIndices: { ...slideLayoutIndices, [slideIndex]: 0 }` in a single atomic `set()`.
3. **Wire in `CarouselCanvas.tsx`:**
   - In `handleDrop`:
     - If dropping a single photo over a `hitFrame`: call `addPhotoFrames(targetSlideIdx, photosToPlace, { targetFrameId: hitFrame.id, isReplace: true })`.
     - If dropping single or multiple photos onto the slide: call `addPhotoFrames(targetSlideIdx, photosToPlace)`.
     - Remove the legacy unbatched loop and naive grid calculation.
</task>

### Task 2: Mode-Aware Routing in `PhotoContextMenu.tsx` and `FilmstripTray.tsx`
**Target Files:**
- `src/features/photos/PhotoContextMenu.tsx`
- `src/features/photos/FilmstripTray.tsx`

1. **Update `PhotoContextMenuProps` and UI Labels:**
   - Add `activeMode?: 'print' | 'carousel'` to `PhotoContextMenuProps`.
   - Render contextual placement labels:
     - Carousel Mode: `isMulti ? \`Place ${count} Photos on Slide\` : 'Place on Active Slide'`
     - Print Mode: `isMulti ? \`Place ${count} Photos on Spread\` : 'Place on Spread Canvas'`
2. **Implement Mode-Aware Placement Dispatch:**
   - When the user clicks the placement button:
     - If `activeMode === 'carousel'`:
       - Retrieve `{ currentCarousel, activeSlideIndex, addPhotoFrames } = useCarouselStore.getState()`.
       - If `currentCarousel` is valid:
         - Dispatch `addPhotoFrames(activeSlideIndex, toPlace)`.
         - Update `photoStore.usedCount` for placed photo IDs.
     - If `activeMode === 'print'`:
       - Execute existing `addPhotosToSpread(activeSpread.id, toPlace)` flow.
3. **Pass `activeMode` from `FilmstripTray.tsx`:**
   - Supply `activeMode={activeMode}` to `<PhotoContextMenu ... />` in `FilmstripTray.tsx`.
</task>

### Task 3: In-Canvas Selected Frame Replacement on Double-Click & Test Suite
**Target Files:**
- `src/features/photos/FilmstripTray.tsx`
- `tests/carousel-drag-context.test.ts`

1. **Refactor Double-Click Handler in `FilmstripTray.tsx`:**
   - In `FilmstripTray.tsx` `onDoubleClick`:
     - When `activeMode === 'carousel'`:
       - Retrieve `{ currentCarousel, activeSlideIndex, selectedFrameId, addPhotoFrames } = useCarouselStore.getState()`.

       - If no frame is selected: invoke `addPhotoFrames(activeSlideIndex, [photo])`.
       - Increment `photoStore.usedCount` for `photo.id`.
2. **Automated Unit & Integration Test Suite:**
   - Create `tests/carousel-drag-context.test.ts` testing:
     - Batch photo drop of 3 photos on a carousel slide creates 3 frames in a single update.
     - Single `Cmd+Z` (`undo()`) rolls back all 3 frames in one step.
     - Smart reflow combines existing slide photos with newly added photos using R-BSP engine, preserving custom border and corner radius attributes.
     - Frame replacement preserves target frame geometry and updates photo references.
     - Double-click and context menu dispatch correctly to carousel store without modifying album store spreads.
   - Run tests via `npx tsx tests/carousel-drag-context.test.ts`.
</task>
