### Anomaly 2: Multi-Photo Drag-and-Drop Aborts in macOS WebKit (Tauri WKWebView)
- **Classification:** WebKit / Tauri Native Drag Failure & MIME Sanitization Bug
- **Confidence:** HIGH

- **Evidence in Code:**
  ```tsx

    const dragImage = document.createElement('canvas');
    dragImage.width = 150;
    dragImage.height = 48;
    const context = dragImage.getContext('2d');

      context.fillStyle = '#182433';

      context.fillStyle = '#f1f5f9';

      e.dataTransfer.setDragImage(dragImage, 18, 24); // <--- FATAL IN WEBKIT

  ```
- **Root Cause Mechanisms:**
  1. **WebKit Bug with Detached `canvas` in `setDragImage`:**
     In macOS WebKit (WKWebView), `e.dataTransfer.setDragImage(canvas)` with a dynamically created `<canvas>` element that is NOT attached to the DOM tree causes WebKit to either throw an unhandled internal exception or immediately abort the native OS drag gesture (WebKit Bug #70845).
     *Single photo drag succeeds* because `ids.length === 1` bypasses this block completely.
     *Multi-photo drag fails 100% of the time* because `ids.length > 1` executes `setDragImage(dragImage)`.
  2. **`text/plain` Payload Only Contains Single ID:**
     Line 364 sets:
     `e.dataTransfer.setData('text/plain', ids[0] || photo.id);`
     If custom types (`application/x-afsn-photo-ids`) are sanitized by macOS `NSPasteboard` during cross-target dragging, the fallback `text/plain` only transmits the first photo ID.
  3. **Immediate `onDragEnd` Store Wipeout:**
     Line 691 sets `usePhotoStore.setState({ draggedPhotoIds: [] })` on `dragend`. In WebKit, if `dragend` fires prior to the completion of the drop event handler, `photoStore.draggedPhotoIds` is wiped to `[]`, leaving `photosToPlace` empty.
  4. **`BatchActionBar` Missing Drag Capability:**
     When 4 photos are selected, the user is presented with the floating `BatchActionBar` ("4 Photos Selected"). Users naturally attempt to grab and drag this bar directly into the carousel slide or album spread, but the bar has no drag listeners.

## 3. Recommended Remediation Plan

### Fix 1: Implement Marquee (Rubberband) Drag Selection in FilmstripTray
- Add pointer events (`onPointerDown`, `onPointerMove`, `onPointerUp`) to `FilmstripTray`'s scrollable container (`bodyRef`).
- When dragging starts on the container background or across cards without clicking a button:
  - Track start coordinate `(startX, startY)` and current coordinate `(currentX, currentY)` relative to the container scroll offset.
  - Render a sleek, semi-transparent marquee rectangle overlay (`styles.marqueeSelectionBox`).
  - Calculate 2D intersection (`AABB`) between the marquee rect and each `.photoCard` bounding client rect.
  - Update `selectedPhotoIds` in real-time.
  - Support `Shift` / `Cmd` modifiers to invert or extend existing selection.

### Fix 2: Repair Multi-Photo Drag-and-Drop for WebKit / Tauri
1. **Fix `setDragImage`:**
   - Either use an in-DOM hidden element or an `Image` object with a data URL, or safely attach the canvas to `document.body` before calling `setDragImage` and remove it afterwards on `dragend`.
2. **Robust Payload Encoding:**
   - Set `text/plain` to `ids.join(',')` instead of `ids[0]`.
   - Update `CarouselCanvas.tsx` and `KonvaEditorCanvas.tsx` to parse comma-separated IDs from `text/plain`.
3. **Make `BatchActionBar` Draggable:**
   - Add `draggable={true}` to `BatchActionBar` with drag handle ("Drag to Place All {count} Photos").
   - Enable users to drag the entire batch directly into slides or spreads.
4. **Preserve `draggedPhotoIds` during Drop Event Cycle:**
   - Defer clearing `draggedPhotoIds` by 100ms or until drop completes.

### Fix 3: Implement Playwright E2E UI Test Suite
- Set up `@playwright/test`.
- Create E2E test script `tests/e2e/filmstrip-drag-select.spec.ts`:
  - Test A: Rubberband marquee drag selection selects multiple photos.
  - Test B: Multi-drag from Filmstrip drops all selected photos onto Social Carousel slide and creates corresponding frames.
  - Test C: Multi-drag from Filmstrip drops all selected photos onto Print Album spread.
  - Run headless test with Playwright to verify end-to-end reliability.
