### 🔴 Dual `window.addEventListener('keydown', ...)` Registration — Confidence: HIGH

**Evidence (file-level):**

**File 1:** [`WorkspaceLayout.tsx` L913-916](../../../src/features/workspace/WorkspaceLayout.tsx)
```ts
useEffect(() => {
  window.addEventListener('keydown', handleKeyDown);
  return () => window.removeEventListener('keydown', handleKeyDown);
}, [handleKeyDown]);
```
This global handler processes **all** album shortcuts (Undo, Redo, Save, Zoom, T for text, Delete/Lock frames, etc.) and is registered unconditionally — it does NOT check `activeMode`.

**File 2:** [`KonvaEditorCanvas.tsx` L1988-1989](../../../src/features/editor/KonvaEditorCanvas.tsx)
```ts

return () => window.removeEventListener('keydown', handleKeyDown);
```
This handler fires on **Delete**, **Arrow keys**, **Cmd+C/V/D/G**, **R** (rotate), **S** (swap), and more — and critically, it runs even when `activeMode === 'carousel'`.

**File 3:** [`KonvaEditorCanvas.tsx` L1307-1308](../../../src/features/editor/KonvaEditorCanvas.tsx) — a second `keydown` handler for Alt+Shift drag preview — also unconditional.

**File 4:** [`CarouselCanvas.tsx` L395-414](../../../src/features/carousel/CarouselCanvas.tsx)
```ts

window.addEventListener('keyup', handleKeyUp);
```
The Carousel's own keyboard handler is limited to **Spacebar pan only**. It has NO handlers for Delete (remove frame), Arrow keys (nudge), Escape (deselect), or any selection/editing shortcut.

**Why it breaks:**

When `activeMode === 'carousel'`:
1. `KonvaEditorCanvas` is **unmounted** from the DOM (React conditional render at `WorkspaceLayout.tsx` L1022-1042)
2. BUT its `useEffect` cleanup runs — so the Konva canvas handlers ARE removed. ✅
3. However, `WorkspaceLayout.tsx`'s `handleKeyDown` (L724–911) remains active and processes **all** album-specific shortcuts against `activeSpreadId`, `activeSpread`, and `selectedFrameIds` — which still exist in store state.
4. This means: pressing `Delete` in carousel mode triggers `deleteSelectedFrames(activeSpread.id)` on the album, not `removePhotoFrame` on the carousel.
5. Pressing `Arrow` keys nudges album frames, not carousel frames.
6. Pressing `Spacebar` in `WorkspaceLayout` triggers `cycleLayout(...)` on **album mode** (L976) via the Spacebar disambiguation state machine — even when carousel is active — because `activeMode` is captured by closure in the `useEffect` dep array at L991.

> [!CAUTION]
> The Spacebar disambiguation effect at `WorkspaceLayout.tsx` L918–991 calls `cycleLayout(shiftHeld ? 'prev' : 'next', activeMode)` passing `activeMode` correctly — BUT the CarouselCanvas's **own** spacebar handler at L396–414 also fires simultaneously, causing a double-fire conflict when both react to `Space`.

## Root Cause Hypothesis

The architecture assumes **one active canvas at a time**, but the keyboard handler in `WorkspaceLayout` was never updated to check `activeMode`. As Phase 10–13 built out the Carousel alongside the Album, the global `window.keydown` listener accumulated album-specific logic without any carousel routing. When `activeMode === 'carousel'`, the album canvas is unmounted but its controlling keyboard logic in `WorkspaceLayout` stays fully active, intercepting every keystroke meant for the carousel and routing it to album-store operations.

## Recommended Actions

### Fix 1 — Gate `WorkspaceLayout` global handler on `activeMode` (Quick Win)
In `WorkspaceLayout.tsx` `handleKeyDown` (L724), add an early return for carousel-specific keys when `activeMode === 'carousel'`:
```ts
// At the top of handleKeyDown, after dialog/input guards:
if (activeMode === 'carousel') {
  // Only global shortcuts (Cmd+S, Cmd+Z, Cmd+E, zoom) should pass through
  // All frame-editing shortcuts (Delete, T, L, R, S, Arrow) must be suppressed
  if (!cmdOrCtrl) return; // suppresses Delete, T, L, G, R, S, Arrow etc.
}
```

### Fix 2 — Add CarouselCanvas keyboard handler for carousel-specific actions (Core Fix)
In `CarouselCanvas.tsx`, add a `useEffect` with a full keyboard handler:
```ts
useEffect(() => {
  const handleKeyDown = (e: KeyboardEvent) => {
    const target = e.target as HTMLElement;
    if (target.tagName === 'INPUT' || target.tagName === 'TEXTAREA' || target.isContentEditable) return;
    
    if (e.key === 'Delete' || e.key === 'Backspace') {
      if (selectedFrameId) { e.preventDefault(); removePhotoFrame(selectedFrameId); setSelectedFrameId(null); }
    } else if (e.key === 'Escape') {
      setSelectedFrameId(null);
    } else if (['ArrowUp','ArrowDown','ArrowLeft','ArrowRight'].includes(e.key)) {
      if (selectedFrameId) { e.preventDefault(); /* nudge frame */ }
    }
  };
  window.addEventListener('keydown', handleKeyDown);
  return () => window.removeEventListener('keydown', handleKeyDown);
}, [selectedFrameId, removePhotoFrame, setSelectedFrameId]);
```

### Fix 3 — Deduplicate Spacebar handler
`CarouselCanvas.tsx` L395-414 handles `Space` for pan **and** `WorkspaceLayout.tsx` L918-991 handles `Space` for layout cycling — both fire simultaneously when in carousel mode. Solution: Move the spacebar pan logic entirely inside `CarouselCanvas` and add a guard `if (activeMode !== 'carousel') return;` in the WorkspaceLayout spacebar handler.
