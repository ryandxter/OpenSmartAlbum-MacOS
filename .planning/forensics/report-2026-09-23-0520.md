## 1. Executive Summary

An investigation was conducted following a reported breakdown where:
1. Dragging/importing photos resulted in an **infinite loading progress banner** (`Importing Photos · Generating previews · RVMR9920.JPG 7 / 7 100% Cancelling...`).
2. All imported photos became instantly and falsely marked with the **`✓ Used`** badge despite not being placed on any spread or carousel slide.
3. Dragging photos from the Filmstrip Tray into the canvas (either Print Album spread or Social Carousel) **failed to place or drop**.
4. Double-clicking any of the affected photos in the Filmstrip Tray was **hard-blocked**.

The investigation revealed three interconnected root causes spanning event lifecycle leakage, premature state mutation, and platform-specific WebKit drag-and-drop payload handling.

## 3. Anomaly Analysis (4 Anomaly Dimensions)

### Anomaly 1: Stuck Loop / Deadlock in Import Progress Lifecycle
- **File:** `src/stores/photoStore.ts` (lines 315–398, 648–687)
- **Mechanism:**
  1. When photos are ingested via `importPathsAndGetPhotos` (`WorkspaceLayout.tsx:271`), it invokes `import_file_paths` in the Rust core directly without registering an `ImportTask` in the store's `importQueue`.
  2. The Rust backend generates thumbnails and previews, broadcasting Tauri IPC events: `photo-import-progress` for each photo (1/7, 2/7 ... 7/7) followed by `photo-import-complete`.
  3. Frontend listener for `photo-import-progress` receives the event and sets `{ isImporting: true, importProgress: payload }`.
  4. **The Defect:** In `photoStore.ts:359-398`, the listener for `photo-import-complete` only updates `importNotice`. It **never sets `isImporting: false` or `importProgress: null`**!
  5. The store relies exclusively on `processNextQueueItem` (called in `executeImportTask.finally`) to reset `isImporting` and `importProgress`. Because `importPathsAndGetPhotos` bypassed the task queue, `processNextQueueItem` is never executed.
  6. When the user attempts to cancel the stuck bar, `cancelImport()` sets `isCancelling: true`. Since no queue task exists, `isCancelling: true` also becomes permanently stuck, producing `Cancelling...` at `100%`.

### Anomaly 2: Premature State Mutation & False Invariant Violation (`usedCount`)
- **File:** `src/features/workspace/WorkspaceLayout.tsx` (lines 278–284)
- **Code:**
  ```typescript
  // WorkspaceLayout.tsx:278
  // Mark photos as used in photoStore
  const newPhotoIdSet = new Set(newPhotos.map((p) => p.id));
  usePhotoStore.setState((s) => ({
    photos: s.photos.map((p) =>
      newPhotoIdSet.has(p.id) ? { ...p, usedCount: (p.usedCount || 0) + 1 } : p
    ),
  }));
  ```
- **Mechanism:**
  - In `handleCanvasFinderDrop`, immediately upon receiving imported photos from `importPathsAndGetPhotos`, `WorkspaceLayout.tsx` **unconditionally increments `usedCount` on all imported photos** *before* placement is even attempted or validated.
  - If the drop coordinates miss an empty slide/spread, if placement fails, or if the drop occurs on the window, the photos are already permanently marked as `usedCount > 0` in memory.
  - In `FilmstripTray.tsx:624`:
    ```typescript
    const isUsed = usedPhotoIdSet.has(photo.id) || photo.usedCount > 0;
    ```
    This causes all 7 photos to be classified as `isUsed = true`, rendering the `✓ Used` overlay and dimming them.

### Anomaly 3: Workflow/UX Blockade
- **File:** `src/features/photos/FilmstripTray.tsx` (line 632)
- **Code:**
  ```typescript
  // FilmstripTray.tsx:631-632
  onDoubleClick={() => {
    if (isUsed) return;
    // ... placement logic ...
  }}
  ```
- **Mechanism:**
  - Because of Anomaly 2, `isUsed` evaluates to `true` for all photos.
  - Line 632 contains an explicit early return: `if (isUsed) return;`.
  - As a result, double-clicking a photo to place it onto the active carousel slide or album spread is completely disabled.

### Anomaly 4: Platform / Protocol Transfer Asymmetry (WebKit Drag Payload Loss)
- **File:** `src/features/carousel/CarouselCanvas.tsx` (lines 381–399) vs `src/features/editor/KonvaEditorCanvas.tsx` (lines 2149–2166)
- **Mechanism:**
  - In `FilmstripTray.tsx:355-365`, `handleCardDragStart` sets drag data:
    ```typescript
    e.dataTransfer.setData('application/x-afsn-photo-ids', JSON.stringify(ids));
    e.dataTransfer.setData('application/json', JSON.stringify(ids));
    e.dataTransfer.setData('text/plain', ids[0] || photo.id);
    ```
  - In macOS `WKWebView` (WebKit), custom MIME types (e.g. `application/x-afsn-photo-ids`) can be sanitized or inaccessible during cross-element drops unless strictly handled.
  - In `KonvaEditorCanvas.tsx:2164`, an explicit defensive fallback was implemented:
    ```typescript
    if (photoIds.length === 0 && transferTypes.includes('application/x-afsn-photo-ids')) {
      photoIds = usePhotoStore.getState().selectedPhotoIds;
    }
    ```
  - **The Defect:** In `CarouselCanvas.tsx:381-399`, this fallback is completely missing. If `getData` returns an empty string, `photoIds` evaluates to `[]`, `photosToPlace` is empty, and `CarouselCanvas` silently aborts the drop without placing any frames or providing feedback.

| **RC-1** | Infinite loading progress bar at `7 / 7 100% Cancelling...` | `src/stores/photoStore.ts:359-398` & `648-687` | In `photo-import-complete` listener, explicitly reset `isImporting: false`, `importProgress: null`, `isCancelling: false`. ## 5. Corrective Action Plan

1. **Fix `photoStore.ts` Event Listener & API Cleanup**:
   - In `setupListeners()` -> `photo-import-complete`, reset `isImporting: false`, `isCancelling: false`, and `importProgress: null` when no further queue items remain.
   - In `importPathsAndGetPhotos()`, wrap in `try ... finally` to ensure `usePhotoStore.setState({ isImporting: false, isCancelling: false, importProgress: null })` is executed.
2. **Fix `WorkspaceLayout.tsx` Placement & `usedCount` Accounting**:
   - Remove unconditional `usePhotoStore.setState` at line 278.
   - Increment `usedCount` only inside successful placement branches (`bestVariation` creation, `addPhotoFrame`, or `addPhotosToSpread`).
3. **Fix `CarouselCanvas.tsx` Drop Ingestion**:
   - Synchronize drag-and-drop extraction logic from `KonvaEditorCanvas.tsx` to `CarouselCanvas.tsx`, adding the `selectedPhotoIds` fallback and `text/plain` parsing.
4. **Relax `FilmstripTray.tsx` Double-Click Restrictions**:
   - Remove `if (isUsed) return;` from `onDoubleClick` so users can place photos freely regardless of current usage status.
