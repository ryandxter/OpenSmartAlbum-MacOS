## 1. Executive Summary

An in-depth forensic investigation was conducted across the codebase and user-reported runtime anomalies in the Tauri desktop environment (`OpenSmartAlbum-MacOS`). Six specific issues were analyzed and cross-referenced with code implementation and runtime evidence from macOS screenshots:

1. **Missing Slide Previews in Carousel Strip:** Slide cards in `SlideNavigator` only render background colors and numbers; no thumbnail preview logic exists.
2. **Dynamic Layouts Broken for Slide 2+:** `carouselStore` actions (`applyDynamicSlideLayoutByIndex`, `cycleSlideLayout`, `autoFlowPhotosToSlides`) assign local layout `x` coordinates without translating them to continuous canvas stage coordinates (`slideStartX + rect.x`), displacing frames to Slide 1.
3. **Seamless Panorama Limited to 4:** Hardcoded array in `carouselLayout.ts` only registers 4 presets.
4. **Keyboard Shortcuts Inoperative:** Classic React stale closure bug in `WorkspaceLayout.tsx` (`activeMode` omitted from `useCallback` dependency array), causing all shortcuts (`Cmd+Z`, `Cmd+Shift+Z`, `Cmd+A`) to continually route to print album actions.
5. **Used Photos Dimmed & Not Readily Reusable:** Aggressive `grayscale(45%)` and `opacity: 0.65` styling makes photos appear permanently disabled, coupled with missing drop-to-replace support on carousel canvas frames.
6. **Mobile Simulator 100% Broken:** Total class mismatch between `PhoneSwipeSimulator.tsx` and `PhoneSwipeSimulator.module.css` (`simulatorBackdrop` vs `overlay`, `phoneChassis` vs `phoneFrame`, etc.), causing the component to render without CSS constraints and blow up full-screen.

## 2. Detailed Findings & Grounded Evidence

### Issue 1: Missing Slide Preview Above Photostrip
* **File:** `src/features/carousel/SlideNavigator.tsx` (lines 43–60)
* **Evidence:**
  ```tsx
  <div
    key={slide.id}
    className={`${styles.slideCard} ${isActive ? styles.slideCardActive : ''}`}
    style={{ backgroundColor: slide.backgroundColor || '#FFFFFF' }}
    onClick={() => setActiveSlide(idx)}
  >
    <span className={styles.slideNumberBadge}>{idx + 1}</span>
  </div>
  ```
* **Analysis:** Unlike `PageNavigator.tsx` which calculates preview projection (`MiniSpreadPreview`) and renders miniature photo elements, `SlideNavigator` only renders an empty white container.
* **Impact:** User sees blank white rectangles in the bottom track instead of slide content previews.

### Issue 2: Dynamic Layouts Only Working on Slide 1
* **File:** `src/stores/carouselStore.ts` (lines 485, 571, 810, 847)
* **Evidence:**
  ```tsx
  // in applyDynamicSlideLayoutByIndex:
  const newPhotoElements: CarouselPhotoFrame[] = chosen.rects.map((rect, i) => ({
    ...
    x: rect.x, // <--- ERROR: rect.x is 0..1080, NOT offset by slideStartX!
    y: rect.y,
    width: rect.width,
    height: rect.height,
  }));
  ```
* **Analysis:** On Slide 1 (index 0), `slideStartX = 0`, so `rect.x` coincidentally works. On Slide 2 (index 1), `slideStartX = 1080`. By assigning `x: rect.x`, frames on Slide 2 are assigned coordinates between `0` and `1080`, physically displacing them onto Slide 1 on the canvas. When clicked, `getSlideIndexAtX` detects `x < 1080` and resets the active slide to Slide 1.
* **Impact:** Applying dynamic layouts to Slide 2+ moves photos backwards to Slide 1, corrupting slide layout state and displaying "No photos on active slide".

### Issue 3: Seamless Panorama Preset Limitation
* **File:** `src/domain/carouselLayout.ts` (lines 300–420)
* **Evidence:**
  The `CAROUSEL_LAYOUT_PRESETS` array defines exactly 4 presets under `category: 'panorama'` (`panorama_2_slide`, `panorama_2_slide_framed`, `panorama_3_slide`, `panorama_2_slide_detail`).
* **Analysis:** `TemplatesPanel.tsx` counts and renders `CAROUSEL_LAYOUT_PRESETS.filter(p => p.category === 'panorama')`. No additional variations (e.g. 4-slide ultra panorama, multi-inset panorama cards, split panoramas) were authored.
* **Impact:** User is constrained to only 4 panorama options.

### Issue 4: Keyboard Shortcuts Not Triggering in Social Carousel
* **File:** `src/features/workspace/WorkspaceLayout.tsx` (lines 845–940)
* **Evidence:**
  ```tsx
  const handleKeyDown = useCallback(
    (e: KeyboardEvent) => {
      if (e.key === 'z' || e.key === 'Z') {
        if (activeMode === 'carousel') {
          // Carousel undo/redo
        } else {
          // Album undo/redo
        }
      }
    },
    [undo, redo, saveProject, ... /* activeMode is MISSING HERE! */]
  );
  ```
* **Analysis:** `handleKeyDown` captures `activeMode` as `'print'` on initial mount and never re-binds when switching to `'carousel'`. All keyboard inputs execute print album routines. In addition, `CarouselCanvas.tsx` registers conflicting listeners that fight for event handling.
* **Impact:** `Cmd+Z`, `Cmd+Shift+Z`, `Cmd+A` and other shortcuts do not affect the carousel in production Tauri runs.

### Issue 5: Used Photos Greyed Out / Disabled UX
* **File:** `src/features/photos/FilmstripTray.module.css` (lines 622–625) & `src/features/carousel/CarouselCanvas.tsx`
* **Evidence:**
  ```css
  .cardUsed {
    opacity: 0.65;
    filter: grayscale(45%);
  }
  ```
* **Analysis:** Once placed, a photo is subjected to opacity dimming and grayscale filtering. This mimics a disabled UI control rather than an informative status badge. Photographers need full-contrast visibility to re-use photos across multiple slides/spreads. Furthermore, `CarouselCanvas` lacks drop-to-replace handling when dropping over existing frames.
* **Impact:** Photos appear un-reusable and difficult to distinguish once used.

### Issue 6: Phone Simulator Broken Display
* **File:** `src/features/carousel/PhoneSwipeSimulator.tsx` vs `PhoneSwipeSimulator.module.css`
* **Evidence:**
  * TSX uses `styles.simulatorBackdrop`, CSS defines `.overlay`.
  * TSX uses `styles.phoneChassis`, CSS defines `.phoneFrame`.
  * TSX uses `styles.phoneNotch`, CSS defines `.notch`.
  * TSX uses `styles.phoneHeader`, CSS defines `.appHeader`.
  * Multiple sub-element classes (`speakerPill`, `cameraDot`, `headerLeft`, `slideIndicator`, `photoFrame`) are completely absent in CSS.
* **Analysis:** Because CSS module class names evaluated to `undefined`, the simulator rendered without any wrapper dimensions, position: fixed backdrop, or chassis overflow clipping. The child `<img>` tags expanded to 100% viewport width, resulting in the massive broken image shown in user screenshot 3.
* **Impact:** The mobile preview modal is visually destroyed and unusable.

## 3. Recommended Remediation Plan (to execute via /gsd-debug)

1. **Implement `MiniSlidePreview` in `SlideNavigator.tsx`:**
   Project photo frames with scaled coordinates and render actual thumbnails, background color, and layout geometry inside each slide card.
2. **Fix World Coordinates in `carouselStore.ts`:**
   In `applyDynamicSlideLayoutByIndex`, `cycleSlideLayout`, and `autoFlowPhotosToSlides`, compute `slideStartX = slideIndex * currentCarousel.slideWidthPx` and set `x: Math.round(slideStartX + rect.x)`.
3. **Expand Seamless Panorama Presets in `carouselLayout.ts`:**
   Add new curated panorama presets (4-slide ultra panorama, 2-slide asymmetric split, 3-slide with dual floating details, 2-slide multi-card collage over panorama, etc.) to bring total presets to 8+.
4. **Fix Keyboard Shortcut Closure & Centralize Routing:**
   Add `activeMode` to `WorkspaceLayout.tsx` dependencies (or use ref / direct store lookup `useEditorStore.getState().activeMode`), and harmonize with `CarouselCanvas`.
5. **Improve Used Photo Badge & Canvas Replacement:**
   Remove disabling `grayscale(45%)` and `opacity: 0.65` from `.cardUsed`. Retain vivid thumbnails with a sleek, discrete counter badge (e.g. `Used 1x`, `Used 2x`). Support dropping photos onto existing frames in `CarouselCanvas` for direct replacement.
6. **Re-align Phone Simulator JSX & CSS Module:**
   Update `PhoneSwipeSimulator.tsx` to use correct class names matching `PhoneSwipeSimulator.module.css` and supply any missing chassis/notch styles.
