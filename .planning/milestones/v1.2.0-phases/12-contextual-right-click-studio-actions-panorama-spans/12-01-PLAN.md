## Tasks

### Task 1: Hero Anchor Biasing in Generative Layout Core
<task id="12-01-T1">
**Title:** Implement Explicit Hero Weighting in `aspectMatcher.ts` and `generator.ts`
**Target Files:**
- `src/domain/layout/aspectMatcher.ts`
- `src/domain/layout/generator.ts`
- `src/domain/adaptiveLayout.ts`

**Details:**
1. In `src/domain/layout/aspectMatcher.ts`:
   - Add `isHero?: boolean` to `PhotoAspectInput`.
   - In `calculateSlotCost`: When `photo.isHero` is true, add heavy penalty `(1.0 - areaRatio) * 20.0` against assigning the hero photo to non-dominant slots. This mathematically guarantees the Hungarian bipartite matching assigns the hero photo to the slot with maximum area.
2. In `src/domain/layout/generator.ts`:
   - Add `heroPhotoId?: string` to `LayoutGeneratorOptions`.
   - When mapping photos to `PhotoAspectInput`, set `isHero: Boolean((options.heroPhotoId && (p.id === options.heroPhotoId || p.photoId === options.heroPhotoId)) || p.isFavorite)`.
   - For candidates generated with hero archetypes (`hero-companion-grid`, `Hero + Companion Stack`), boost variation harmony score when a hero photo is designated.
3. In `src/domain/adaptiveLayout.ts`:
   - Add `isHero?: boolean` to `AdaptivePhoto`.
</task>

### Task 2: Store Actions for Full-Bleed Promotion & Hero Assignment
<task id="12-01-T2">
**Title:** Implement `promoteToFullBleedSpread` and `setHeroPhotoOnSpread` in `albumStore.ts`
**Target Files:**
- `src/stores/albumStore.ts`

**Details:**
1. Add `promoteToFullBleedSpread: (spreadId: string, frameId: string) => void` to `AlbumState`:
   - Push snapshot to `useHistoryStore.getState().pushState(currentAlbum)`.
   - Calculate physical full bleed coordinates:
     - $x = -\text{bleed}, y = -\text{bleed}$
     - $\text{width} = \text{spreadWidth} + 2 \cdot \text{bleed}$
     - $\text{height} = \text{spreadHeight} + 2 \cdot \text{bleed}$
   - Update target frame to full bleed dimensions, rotation 0, cropX 0, cropY 0.
   - If other photos exist on the spread ($N > 1$):
     - Extract remaining $(N - 1)$ photos.
     - Insert a new interior spread directly following current spread via `createInteriorSpread`.
     - Synthesize optimal dynamic layout for the remaining photos via `generateDynamicVariations` and `buildSpreadElementsFromVariation`.
     - Recalculate page numbers with `recalculateAlbumPageNumbers`.
   - Set `saveStatus: 'unsaved'`.
2. Add `setHeroPhotoOnSpread: (spreadId: string, frameId: string) => void` to `AlbumState`:
   - Push snapshot to `useHistoryStore.getState().pushState(currentAlbum)`.
   - Find target frame and target photo.
   - Run `generateDynamicVariations` with `heroPhotoId: targetFrame.photoId || targetFrame.id`.
   - Replace spread photo frames with Variation 0.
</task>

### Task 3: Context Menu Integration & Spine Clearance Guides in Canvas
<task id="12-01-T3">
**Title:** Context Menu Actions and Non-Printing Spine Warning in `KonvaEditorCanvas.tsx`
**Target Files:**
- `src/features/editor/KonvaEditorCanvas.tsx`

**Details:**
1. In `getContextMenuItems()` in `KonvaEditorCanvas.tsx`:
   - When a single photo frame is selected:
     - Add `Set as Full Bleed Spread (2-Page Panorama)` (disabled on cover spreads, enabled on interior spreads).
     - Add `Set as Hero / Anchor Photo` (enabled when current spread contains $\ge 2$ photos).
2. Spine Clearance Protection (CTX-04):
   - In Layer 3 (Overlay guides), compute whether any photo frame's focal center overlaps the center spine exclusion corridor ($X_{\text{spine}} \pm 19\text{mm}$).
   - If a violation is detected on an interior spread, render:
     - Subtle non-printing amber corridor (`fill="rgba(245, 158, 11, 0.08)"`, dashed borders `#F59E0B`).
     - Non-printing warning badge at top of spine: `⚠️ Subject in Spine Binding Zone (19mm)`.
</task>
