# Plan 10-01: Pure TypeScript Mathematical Layout Engine Core

**Phase:** 10 - Dynamic Generative Layout Core & Non-Destructive Studio Cycling
**Plan ID:** 10-01
**Goal:** Implement a pure TypeScript geometric partitioner, equal-height/width strip normalizers, Kuhn-Munkres (Hungarian) aspect matcher, and unified layout generator in `src/domain/layout/` capable of synthesizing valid aspect-preserving partitions for any $N \in [1..15]$ photos without static templates.
**Requirements:** GEN-01, GEN-04, GEN-05
**Dependencies:** None (pure domain algorithms with zero external runtime dependencies)

---

## Context & Architectural Strategy

Legacy layout generation in `adaptiveLayout.ts` relied on a mix of hardcoded heuristics, branch-and-bound permutation search capped at $N \le 7$, and greedy fallbacks for $N \ge 8$. This led to poor matching on high photo counts and lacked multi-photo strip normalization, causing fractional sub-pixel rounding seams (Pitfall 1).

This plan creates four pure TypeScript domain modules under `src/domain/layout/`:
1. `bspEngine.ts`: Slicing tree decomposition applying harmonic editorial split proportions ($0.618, 0.667, 0.500, 0.750$) with discrete spacing deduction and `minSlotDimension` guards.
2. `rowColumnNormalizer.ts`: Equal-height row (justified gallery) and equal-width column (vertical masonry) normalization with cumulative edge boundary snapping to guarantee 0px hairline rounding seams.
3. `aspectMatcher.ts`: $O(N^3)$ Kuhn-Munkres (Hungarian) algorithm minimizing scale-invariant logarithmic aspect cost ($|\ln P_i - \ln S_j|$), cross-orientation penalty ($2.5$), and hero area weighting.
4. `generator.ts`: Unified facade synthesizing ranked `AdaptiveLayoutVariation` candidates for any $N \in [1..15]$ across single slides and multi-page spreads.
5. `__tests__/generativeLayout.test.ts`: Automated mathematical verification suite executed via `npx tsx`.

```
src/domain/layout/
├── bspEngine.ts             # Slicing tree partitioner with harmonic editorial proportions
├── rowColumnNormalizer.ts   # Justified strip solvers with cumulative edge snapping
├── aspectMatcher.ts         # Hungarian O(N^3) assignment & log-aspect energy minimization
├── generator.ts             # Unified facade generating strictly N slots for N photos
└── __tests__/
    └── generativeLayout.test.ts # Mathematical test suite (npx tsx)
```

### Task 1: Recursive Binary Space Partitioning Engine (`bspEngine.ts`)

<task id="10-01-T1">
**Title:** Implement Slicing Tree Partitioning with Harmonic Editorial Ratios
**Target Files:**
- `src/domain/layout/bspEngine.ts`

**Implementation Details:**
1. Define data structures:
   ```typescript
   import { RectBounds } from '../templates';

   export type SplitAxis = 'horizontal' | 'vertical';

   export interface BspSplitNode {
     type: 'split';
     axis: SplitAxis;
     ratio: number;
     left: BspNode;
     right: BspNode;
     bounds: RectBounds;
   }

   export interface BspLeafNode {
     type: 'leaf';
     bounds: RectBounds;
     slotIndex: number;
   }

   export type BspNode = BspSplitNode | BspLeafNode;

   export interface BspPartitionOptions {
     container: RectBounds;
     leafCount: number;
     spacing: number;
     minSlotDimension?: number; // Minimum width/height (default 40px)
     seedVariant?: number; // Integer index selecting split axis & ratio combinations
   }
   ```
2. Define harmonic editorial split ratios:
   - Golden Hero: `0.618` and `0.382`
   - Two-Thirds: `0.667` and `0.333`
   - Half Balance: `0.500`
   - Three-Quarter Hero: `0.750` and `0.250`
3. Implement `partitionBsp(options: BspPartitionOptions): RectBounds[]`:
   - If `leafCount <= 1`, return `[options.container]`.
   - Recursively split container:
     - For vertical cut:
       `wLeft = Math.round((bounds.width - spacing) * ratio);`
       `wRight = bounds.width - spacing - wLeft;`
       Check bounds: if `wLeft < minSlotDimension` or `wRight < minSlotDimension`, fallback to symmetric `0.5` or abort branch.
       `bLeft = { x: bounds.x, y: bounds.y, width: wLeft, height: bounds.height };`
       `bRight = { x: bounds.x + wLeft + spacing, y: bounds.y, width: wRight, height: bounds.height };`
     - For horizontal cut:
       `hTop = Math.round((bounds.height - spacing) * ratio);`
       `hBottom = bounds.height - spacing - hTop;`
       Check bounds: if `hTop < minSlotDimension` or `hBottom < minSlotDimension`, fallback to symmetric `0.5`.
       `bTop = { x: bounds.x, y: bounds.y, width: bounds.width, height: hTop };`
       `bBottom = { x: bounds.x, y: bounds.y + hTop + spacing, width: bounds.width, height: hBottom };`
   - Recursively allocate `kLeft` leaves to left child and `kRight = leafCount - kLeft` leaves to right child, where $kLeft = \lceil leafCount / 2 \rceil$ or chosen by variant permutation.
   - Return flattened leaves in deterministic top-to-bottom, left-to-right reading order.
4. Export helper `generateBspVariants(container: RectBounds, leafCount: number, spacing: number, maxVariants?: number): RectBounds[][]` producing diverse topological cuts by varying axis order and ratio sequence.

### Task 2: Equal-Height Row & Equal-Width Column Normalizers (`rowColumnNormalizer.ts`)

<task id="10-01-T2">
**Title:** Implement Multi-Photo Strip Solvers with Cumulative Edge Snapping
**Target Files:**
- `src/domain/layout/rowColumnNormalizer.ts`

**Implementation Details:**
1. Define functions:
   ```typescript
   import { RectBounds } from '../templates';

   export interface RowNormalizationOptions {
     container: RectBounds;
     photoAspects: number[]; // w_i / h_i (> 0)
     spacing: number;
     maxHeight?: number;
     verticalAlign?: 'top' | 'center' | 'bottom';
   }

   export interface ColumnNormalizationOptions {
     container: RectBounds;
     photoAspects: number[]; // w_j / h_j (> 0)
     spacing: number;
     maxWidth?: number;
     horizontalAlign?: 'left' | 'center' | 'right';
   }
   ```
2. Implement `normalizeEqualHeightRow(options: RowNormalizationOptions): RectBounds[]`:
   - Number of photos $k = \text{photoAspects.length}$. If $k = 0$, return `[]`.
   - Calculate usable width: $W_{\text{usable}} = \text{container.width} - (k - 1) \times \text{spacing}$.
   - Sum of aspect ratios: $S_r = \sum_{i=0}^{k-1} r_i$.
   - Ideal row height: $H_{\text{ideal}} = W_{\text{usable}} / S_r$.
   - If `maxHeight` is specified and $H_{\text{ideal}} > \text{maxHeight}$, clamp row height $H_{\text{row}} = \text{maxHeight}$, otherwise $H_{\text{row}} = H_{\text{ideal}}$.
   - Compute vertical offset $Y_{\text{start}}$ based on `verticalAlign` (defaults to 'center').
   - **Cumulative Discrete Boundary Snapping (Zero-Seam Guarantee - Pitfall 1):**
     Do NOT compute $w_i = \text{round}(H \cdot r_i)$ independently.
     Compute cumulative edge coordinates:
     ```typescript
     let runningAspectSum = 0;
     const edges: number[] = [container.x];
     for (let i = 0; i < k; i++) {
       runningAspectSum += photoAspects[i];
       const edgeX = Math.round(container.x + (runningAspectSum / S_r) * W_usable + i * spacing);
       edges.push(edgeX);
     }
     const rects: RectBounds[] = [];
     for (let i = 0; i < k; i++) {
       const x = edges[i] + (i > 0 ? spacing : 0);
       const nextEdge = edges[i + 1];
       const width = nextEdge - x;
       rects.push({
         x,
         y: Math.round(yStart),
         width: Math.max(1, width),
         height: Math.round(hRow),
       });
     }
     ```
   - Mathematical guarantee: $\text{edge}[k] = \text{container.x} + W_{\text{usable}} + (k - 1) \cdot \text{spacing} \equiv \text{container.x} + \text{container.width}$. Zero rounding gap!
3. Implement `normalizeEqualWidthColumn(options: ColumnNormalizationOptions): RectBounds[]`:
   - Number of photos $m = \text{photoAspects.length}$.
   - Usable height: $H_{\text{usable}} = \text{container.height} - (m - 1) \times \text{spacing}$.
   - Sum of inverse aspects: $S_{\text{inv}} = \sum_{j=0}^{m-1} (1 / r_j)$.
   - Ideal column width: $W_{\text{ideal}} = H_{\text{usable}} / S_{\text{inv}}$.
   - Clamp to `maxWidth` if provided; apply `horizontalAlign`.
   - Apply cumulative vertical boundary snapping along $Y$ axis.
4. Export both normalizers with unit helpers.

### Task 3: Hungarian / Kuhn-Munkres Aspect Matcher (`aspectMatcher.ts`)

<task id="10-01-T3">
**Title:** Implement Optimal Kuhn-Munkres Assignment & Log-Aspect Energy Cost
**Target Files:**
- `src/domain/layout/aspectMatcher.ts`

**Implementation Details:**
1. Define types:
   ```typescript
   import { RectBounds } from '../templates';

   export interface PhotoAspectInput {
     aspect: number; // width / height
     rating?: number; // 0 to 5
     isFavorite?: boolean;
   }

   export interface MatchResult {
     mapping: number[]; // photo[i] -> slot[mapping[i]]
     score: number; // 0..100 composite visual harmony score
     avgCropPenalty: number; // 0.0 (perfect) to 1.0 (severe)
   }
   ```
2. Implement scale-invariant log-aspect cost and orientation penalty:
   ```typescript
   export function calculateSlotCost(
     photo: PhotoAspectInput,
     slot: RectBounds,
     maxSlotArea: number
   ): number {
     const pAspect = photo.aspect > 0 ? photo.aspect : 1.5;
     const sAspect = slot.height > 0 ? slot.width / slot.height : 1.5;

     // 1. Scale-invariant log-aspect distance
     const aspectCost = Math.abs(Math.log(pAspect) - Math.log(sAspect));

     // 2. Cross-orientation mismatch penalty (landscape in portrait or vice versa)
     const isPhotoLandscape = pAspect >= 1.05;
     const isPhotoPortrait = pAspect <= 0.95;
     const isSlotLandscape = sAspect >= 1.05;
     const isSlotPortrait = sAspect <= 0.95;

     let orientPenalty = 0;
     if ((isPhotoLandscape && isSlotPortrait) || (isPhotoPortrait && isSlotLandscape)) {
       orientPenalty = 2.5; // Significant deterrent against orientation mismatch
     }

     // 3. Hero importance weighting: high-star / favorite photos should receive larger slots
     let heroBonus = 0;
     const isHero = (photo.rating && photo.rating >= 4) || photo.isFavorite;
     if (isHero && maxSlotArea > 0) {
       const slotArea = slot.width * slot.height;
       const areaRatio = slotArea / maxSlotArea; // 1.0 = largest slot
       heroBonus = (1.0 - areaRatio) * 1.5; // Penalty for placing hero in smaller slot
     }

     return aspectCost + orientPenalty + heroBonus;
   }
   ```
3. Implement classical Kuhn-Munkres algorithm `solveHungarian(costMatrix: number[][]): number[]`:
   - Handles any $N \times N$ cost matrix where $N \le 15$ in $O(N^3)$ steps.
   - If rows $N \ne$ columns $M$, pad with dummy high-cost entries or clamp.
   - Returns optimal 1-to-1 permutation vector $\pi$ where $\pi[i] = j$ denotes photo $i$ assigned to slot $j$.
4. Implement `matchPhotosToSlots(photos: PhotoAspectInput[], slots: RectBounds[]): MatchResult`:
   - Constructs $N \times N$ matrix using `calculateSlotCost`.
   - Runs `solveHungarian`.
   - Computes composite visual score:
     $S = \max(0, \min(100, \text{round}(100 - (\text{totalCost} / N) \times 25)))$.
   - Returns mapping and score.

- Hero photo awarded largest slot

### Task 4: Unified Generative Facade (`generator.ts`)

<task id="10-01-T4">
**Title:** Implement Multi-Archetype Layout Synthesizer for $N \in [1..15]$
**Target Files:**
- `src/domain/layout/generator.ts`

**Implementation Details:**
1. Define interface:
   ```typescript
   import { RectBounds } from '../templates';
   import { AdaptivePhoto, AdaptiveLayoutVariation } from '../adaptiveLayout';
   import { PhotoFrameElement } from '../editor';

   export interface LayoutGeneratorOptions {
     containerWidth: number;
     containerHeight: number;
     spacing: number;
     isSpread: boolean;
     isCover?: boolean;
     gutterWidth?: number;
     safeMarginTop?: number;
     safeMarginBottom?: number;
     safeMarginOutside?: number;
     safeMarginSpine?: number;
     lockedElements?: PhotoFrameElement[];
   }
   ```
2. Implement `generateDynamicVariations(options: LayoutGeneratorOptions, photos: AdaptivePhoto[]): AdaptiveLayoutVariation[]`:
   - Invariant: If `photos.length === 0`, return `[]`.
   - $N = \text{photos.length}$.
   - Determine usable bounds:
     - For single container (slide or cover): apply margins to compute usable bounding box.
     - For 2-page spread: split into `leftPageArea` and `rightPageArea` separated by `gutterWidth`, or single `spreadArea`.
   - Synthesize topological slot sets according to density tier:
     - **Tier 1 ($N = 1$):** Full Bleed, Inset Margin, Centered Mat (Square / 4:5 / 16:9).
     - **Tier 2 ($N = 2$):** Equal-Height Row, Equal-Width Column, Golden Split (61.8% / 38.2%), Left/Right Page (if spread).
     - **Tier 3 ($N \in [3..6]$):**
       - Editorial BSP slices with harmonic ratios ($0.618, 0.667, 0.5$).
       - Full row / column justified strips via `rowColumnNormalizer`.
       - Hero + Side Stack (1 dominant hero slot + $(N-1)$ companion slots).
       - Symmetric grids (e.g. $2\times 2$ for 4, $3\times 2$ for 6).
     - **Tier 4 ($N \in [7..15]$):**
       - Spread mode: Combinatorial partition across left/right pages $(n_L, n_R)$ where $n_L + n_R = N$ (e.g. for $N=7$: 4+3, 3+4, 5+2, 1+6).
       - Slide mode: Hero + Filmstrip grid, Masonry multi-row strips ($3\times 3, 4\times 3, 5\times 3$), balanced BSP slicing trees.
   - For every candidate slot set:
     - Assert `candidate.length === N`.
     - Run `matchPhotosToSlots` from `aspectMatcher.ts`.
     - Build `AdaptiveLayoutVariation`:
       - `id`: Unique deterministically generated variation ID (e.g. `dyn-bsp-3-gold-0`)
       - `name`: Descriptive editorial name (e.g. "Golden Hero with 2-Stack", "Justified Triptych Row")
       - `description`: Human-readable summary
       - `rects`: The geometric slots
       - `tags`: Classification tags (`'generative'`, `'harmonic'`, `'justified'`)
       - `score`: Visual harmony match percentage ($0..100$)
       - `cropPenalty`: Average crop penalty ($0.0..1.0$)
       - `fingerprint`: Photo orientation fingerprint (e.g. "2L+1P")
       - `photoAssignments`: Hungarian assignment mapping
   - Deduplicate visually identical variations.
   - Sort candidates by `score` descending.
